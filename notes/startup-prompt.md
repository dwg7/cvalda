## 1. プロジェクトの目的

北海道を対象に、GSI の建物（bvmap 系ベクトルタイル）に**写っていない建物**を、Overture Maps の建物データで**ブラウザ上で補う**地図ビューア兼データ書き出しツールを作ります。

- 都市部は公式データが良く、郊外・農村部は Overture（OSM、Esri Community Maps、Microsoft/Google の機械学習など）のほうが建物が多い場合がある、という観察が出発点です。
- 公式データを土台にし、Overture は「公式に無い建物」だけを足します。公式を置き換えません。
- 融合は、**エンドユーザーの操作（ボタン、表示範囲）を引き金に、ブラウザ上で計算**します。サーバー側の事前結合データは作りません。理由は、ライセンスの混ざり方（Overture の建物は OSM を含み ODbL。GSI データには出典・測量法上の扱いがある）を、配布物ではなく利用者の手元の計算に置くためです。
- ビューアの名前は cvalda です（由来は気にしなくてよい）。

## 3. 技術と構成の決まり

- Vite + TypeScript + MapLibre GL JS + pmtiles（必要なら MLT のデコーダ）。依存は npm で入れ、版は lockfile に固定。
- **`docs/` は出力専用です。** 手で書いたものを置かない。`npm run build` の結果だけが入る。GitHub Pages がここから配信します。
- ビルド出力は、**CSS と JS を HTML に埋め込んだ単一の `index.html`**、ファイル名に**ハッシュを入れない**設定にします。
  - `vite-plugin-singlefile` などで埋め込む（使う版は、導入時に確認して固定）。
  - Web Worker は、`new Worker(new URL('./x.worker.ts', import.meta.url), { type: 'module' })` ではなく、単一ファイルに収まる形（Vite の `?worker&inline`）を使う。うまくいかない場合は、その理由を記録し、案を hfu に出す。
  - `rollupOptions.output` の `entryFileNames` / `chunkFileNames` / `assetFileNames` からハッシュを除く。
  - `base: './'`、`build.outDir: 'docs'`、`emptyOutDir: true`。
- `public/` に静的ファイル（`.nojekyll`、アイコン、小さなサンプルデータ）を置く。これはビルド時に `docs/` へコピーされる。
- 手書きの文書は `docs/` ではなく、`README.md`、`AGENTS.md`、`notes/` に置く。
- 開発サーバーは `npm run dev`。ビルド後の確認は `npm run preview`。
- 運用の目標端末：**RAM 4 GB の Chromebook でも動くこと**（hfu が検証する）。重い処理は Worker に出し、メインスレッドを止めない。

## 4. 設計の核

### 4.1 融合の考え方

- 融合は、ブラウザ上で、表示範囲のタイルについて計算します。少し遅れて補完が現れてもかまいません（先に公式を出し、あとから補う）。
- 判定の指標は、**「Overture の建物のうち、公式の建物に覆われている面積の割合」** を第一にします（タイルの境界で図形が切られても、割合なら崩れにくいため）。割合がしきい値以上なら「公式に既にある」、それ未満なら「公式に無い」とみなし、Overture から採る。しきい値は設定可能にし、初期値は 0.5 付近から測定で決める。
- Overture 自身の重複排除は IoU > 0.5 を同一とする方式です。Rapid エディタの重なり判定の正確なアルゴリズムは**確認できていません**。真似をせず、上の割合方式を自前で作り、その旨を記す。
- 計算は表示範囲のタイル単位で行い、結果をタイルごとにキャッシュします。ズームが低すぎる間は計算しない（細かい建物が出る最大ズーム付近だけ）。1 タイルあたりの地物数に上限を設ける。

### 4.2 三つのモード

1. 公式主体＋Overture 補完（既定）
2. 重ね合わせ（公式と Overture を両方そのまま表示）
3. Overture 主体＋公式補完

建物の**出自を色で区別**します（公式、Overture、重なり）。凡例を付け、色は色覚多様性に配慮した組み合わせにする。

### 4.3 書き出し

- 書き出しは、**表示しているタイルの内容から、ブラウザ上で**作ります（Overture を含む）。サーバーには何も置かない。
- 最初は GeoJSON、次に FlatGeobuf。範囲（bbox）の大きさに上限を設け、超えたら案内を出す。
- 各地物に `source`（official / overture）を付ける。Overture 由来は元の `id` を残す。
- **ライセンス：** 書き出しファイルと画面に、出典を必ず付ける（GSI の出典表記、Overture／OSM の表記）。

### 4.4 Cloud Optimized GeoParquet について

- 公開されていなければ、**ベクトルタイルだけで進めます。** 公開されていれば、第二の道として次の二つに使う：
  1. 手元で DuckDB を使い、ある地域の結合を正確に計算し、ブラウザ計算の精度を測る「答え合わせ」。
  2. あとで、Overture 部分を元の形で書き出す高精細な経路。
- 最初の実装には、GeoParquet を入れないでください。
